# @hypercarrier/pi-openai-blackmagic-compact v0.1.0-rc.13

rc.13 restores remote compaction input on Pi 0.86 and later. See the
[rc.12 GitHub release](https://github.com/deephbz/pi-openai-blackmagic-compact/releases/tag/v0.1.0-rc.12)
for the prior command-control boundary.

## Pi 0.86 provider context

- Pi-ai 0.86 providers read the system prompt and tool declarations only from
  transcript system messages. Blackmagic passed a raw Context to the native
  serialization probe, so remote compaction input lost both.
- Blackmagic now normalizes the Context when pi-ai provides
  `normalizeContext`. Older hosts keep the raw Context.

## Verification and limits

- The locked Pi 1.0.0 suite passes 101 tests. Pi 0.99.1 and 0.83.0 pass 99
  tests; the two excluded tests check Git-only artifacts.
- The readiness property oracle now uses the compaction preparation that Pi
  builds for `session_before_compact`, because pi-agent-core 1.0.0 removed the
  harness that the oracle imported.
- The package declares Pi peers `>=0.83.0` without an upper bound. These
  results do not establish runtime compatibility across every peer version.
- Authenticated replay evidence covers one Codex model pair. Generic endpoint
  live acceptance and other provider canaries remain unverified.

After publication, correct only with a higher version. Do not rewrite tags,
replace package bytes, or force-push history.
