# @hypercarrier/pi-openai-blackmagic-compact v0.1.0-rc.12

rc.12 adds Session-local controls for new remote compaction attempts on the
published rc.11 behavior. See the [rc.11 GitHub release](https://github.com/deephbz/pi-openai-blackmagic-compact/releases/tag/v0.1.0-rc.11)
for the prior replay, timeline, and route-recognition boundary.

## Controls

- `/blackmagic status|enable|disable` replaces `/blackmagic-status`.
  Arguments are strict, usage is reported for unknown or extra arguments, and
  completion covers all three subcommands.
- Sessions default to enabled. `disable` prevents only new remote compaction
  attempts, so Pi uses native compaction. Saved-checkpoint replay remains
  active, including when a provider rejects that replay. `enable` restores new
  remote attempts.
- A toggle persists a typed, namespaced custom Session entry outside model
  context. The latest valid setting across Session entries survives tree
  navigation. Copied forks inherit setting entries copied into the fork. New
  Sessions default to enabled. Repeating the current setting is idempotent.
- A compaction hook snapshots the setting at entry. Disabling during an
  in-flight remote attempt does not cancel that attempt. Readiness rechecks the
  setting before its final notice. Persistence failures leave the prior mode
  active.

## Verification and limits

- The locked Pi 0.83.0 suite passes 99 tests. Package verification and pack
  checks pass.
- The package declares Pi peers `>=0.83.0` without an upper bound. The 99-test
  result does not establish runtime compatibility across every peer version.
- Pi 0.85.1 and 0.86.1 comparisons retained 12 and 16 baseline failures.
  Those comparisons covered the prior 91-test tip and remain compatibility
  limits, not new rc.12 failures.
- Authenticated replay evidence covers one Codex model pair. Generic endpoint
  live acceptance and other provider canaries remain unverified.
- A UI-only tail can report readiness while Pi declines native `/compact` work.
