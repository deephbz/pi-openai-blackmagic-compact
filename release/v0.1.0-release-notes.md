# @hypercarrier/pi-openai-blackmagic-compact v0.1.0

0.1.0 is the first stable release. It carries everything in
[rc.13](v0.1.0-rc.13-release-notes.md) and adds cooperation with an external
compaction lifecycle controller. From this release, Blackmagic uses stable
semantic versions published to npm `latest`.

## Cooperating compaction methods

- A lifecycle controller can claim the selected compaction method with an
  `hc.compaction-method` event on `pi.events`. An active claim suppresses new
  Blackmagic generation before authorization or network work.
- Releases match by owner and token, including token-only releases. An old
  release cannot clear a newer claim. Claims clear at Session start, shutdown
  and tree change.
- The claim changes no saved preference and never disables persisted
  checkpoint replay. `/blackmagic status` reports an active claim without a
  preflight call. See [docs/current/README.md](../docs/current/README.md).

## Verification and limits

- The locked Pi 1.0.0 suite passes 102 tests.
- The package declares Pi peers `>=0.83.0` without an upper bound. These
  results do not establish runtime compatibility across every peer version.
- Authenticated replay evidence covers one Codex model pair. Generic endpoint
  live acceptance and other provider canaries remain unverified.
- Extensions that do not implement the claim signal remain outside the
  arbitration guarantee.

After publication, correct only with a higher version. Do not rewrite tags,
replace package bytes, or force-push history.
