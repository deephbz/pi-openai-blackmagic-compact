## Acceptance experiment

The fixture placed a synthetic nonce only in an early assistant message.
Native preparation excluded that message from retained plaintext. The test
loaded the packed extension with empty tools and no private context files.

1. `gpt-5.6-luna` compacted the fixture. The request returned HTTP 200.
   Pi persisted `remote_applied`, an empty native summary, and a nonempty
   opaque checkpoint. Its producer identity remained `gpt-5.6-luna`.
2. A fresh process reopened the session with `gpt-5.6-sol` on the same
   Codex route. Its normal request returned HTTP 200 and recalled the nonce.
   Inspection of a decompressed copy of the outgoing request confirmed the
   opaque checkpoint and no plaintext nonce in any non-compaction input,
   instructions, or tools. The original request bytes remained unchanged.

The test made no intermediate recall request. A persisted counter limited
this corrective experiment to two dispatches. It incremented before dispatch,
failed closed on missing or corrupt state, forced SSE, and blocked WebSocket.
Independent local tests verified the counter and native retained-context cut.
Independent product review accepted the corrected nonce proof.

Separate installed CLI/RPC testing also produced `remote_applied`. The first
RPC driver closed stdin too early and aborted asynchronous compaction. A
response-aware driver corrected that test defect.

## Limits

- This proves one same-route model pair. It does not prove universal model or
  provider compatibility. OpenAI and Azure live acceptance remain unverified.
- Earlier SDK/RPC/TUI trials did not establish a reliable total egress count.
  The two-request bound applies only to the corrective experiment above.
- Earlier recall trials retained nonce-bearing assistant plaintext. They do
  not prove opaque knowledge survival.
- Checkpoint plus UI-only tail can still report ready when Pi declines native
  compaction. This known false positive remains disclosed.
- Release-source tests, package verification, workflow dry run, human review,
  and registry verification remain separate release gates. Documentation
  changes after this canary require a new package tuple; this record retains
  the exact artifact that received the authenticated test.
